# How UniSkilled is translated

Six languages: English (default), Deutsch, العربية, Türkçe, Français, Español. The plan, decisions
and design are in the "UniSkilled multilingual system" doc (approved 10 Nov 2026).

## The three rules

1. **English never changes because of translation.** The language build removes its markers from
   English pages, and CI proves every English file is byte-for-byte what the plain build produces
   (`.github/workflows/pages.yml`). Before the first publish, every English file is also compared
   with the live site (`scripts/compare-live.mjs`).
2. **The logo is never changed or moved.** Same file and size in every language; in Arabic the
   layout mirrors but the logo stays on the left (`logoStaysLeft` in `locales/languages.json`).
3. **The website language is not the language a tutor teaches in.** `users.ui_locale` = what the
   menus say; the languages a person speaks/teaches in are a separate list. Never mix them.
   That list is `public.user_languages` (code + level), shown with `language-picker.js`, changed
   only through `set_my_languages()`. Tutors' lists are public (the "Teaches in" filter);
   everyone else's are private.

## Where things are

| What | Where |
| --- | --- |
| Languages, direction, live or hidden | `locales/languages.json` |
| Interface text | `locales/<lang>/<area>.json` (English in `locales/en/`) |
| Agreed terms, style per language, banned words | `locales/glossary.json` |
| Who reviewed what | `locales/review.json` |
| Runtime for text built in JavaScript | `i18n.js` (`I18N.t`, `I18N.h`, `I18N.money`, `I18N.date`, …) |
| Builds /de/, /ar/, … | `scripts/build-locales.mjs` |
| Checks | `tests/site/i18n.test.mjs` (`npm run test:i18n`), part of CI |

## Marking text in a page

```html
<h1 data-i18n="home.hero.title">Find a tutor who has taken your exact course</h1>
<input data-i18n-attr="placeholder:find.search" placeholder="Search a subject">
```
Write markers exactly like that (one space before, double quotes) so removing them restores the
original bytes. Put `data-i18n` on the innermost element that holds the words, never on a logo.

In JavaScript, keep the English in the code:
```js
el.textContent = I18N.t('booking.sent', 'Request sent to {{tutor}}', { tutor: name });
list.innerHTML = I18N.h('find.count', { one: '{{count}} tutor', other: '{{count}} tutors' }, { count: n });
price.textContent = I18N.money(25, 'EUR');
```
`t` = plain text; `h` = safe for `innerHTML` (values escaped). On English pages both return the
English written there, so English output does not change.

## Arabic (right-to-left)

The English files are never edited for Arabic. The build mirrors the layout in the /ar/ copies only
(`scripts/rtl.mjs`): stylesheets with rtlcss, `style="…"` values, and styles inside JavaScript text
strings (found with the acorn tokenizer, so code is never touched; a test proves every script on the
site still parses with identical code). Arabic letters use IBM Plex Sans Arabic via `fonts/arabic.css`,
loaded only on Arabic pages. The logo stays on the LEFT: the shared header keeps its English order,
and any other header or bar holding the logo does too (three separate rules), checked in a real
browser by `tests/e2e/rtl.spec.ts` on desktop and phone. Language folders get a copy of the shared
files so paths built by scripts (like the header logo) work there; videos stay shared.

Preview any page mirrored (English words, Arabic layout) without publishing:
`node scripts/build-locales.mjs --site . --rtl-preview index.html,signin.html --out /tmp/rtl`
then serve `/tmp/rtl` and open `/ar/index.html`.

Arrows and chevrons that point "forward" must point left in Arabic: give their icon `class="flip-rtl"`
(or write ← in the Arabic text) when the page is translated.

## Quality rules (enforced by tests)

- Same keys as English; same `{{placeholders}}`; same HTML tags.
- Every plural form the language needs (Arabic: zero, one, two, few, many, other).
- Glossary terms used consistently; banned words never used (e.g. "escrow", "teacher").
- French: narrow no-break space (U+202F) before `: ; ! ?` and inside `« »`.
- Payment, account, email and legal areas go live in a language only after review
  (`locales/review.json`); until then those pages stay English in that language.
- A page is only published in a language when ALL its text is translated; otherwise visitors get
  the English page. Nobody sees a half-translated page.
- Test any page with `?i18n=qps`: translated text looks ⟦ƒöŕ ţĥíš⟧, so leftover English stands out.

## Adding a language

1. Add a block to `locales/languages.json` (code, native name, direction, Intl locale, `live: false`)
   and the same code to `LANGS` in `i18n.js` (the tests check they match).
2. Create `locales/<code>/`, add the terms for it to `locales/glossary.json` and its style line.
3. Run `npm run test:i18n`; translate what is listed; get it reviewed; record that in `review.json`.
4. Set `live: true`. The build publishes its pages; nothing else changes.
